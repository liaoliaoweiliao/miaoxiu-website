# 展览减少动态下主动播放

## 定位与实现

原工程两个文件同步后，用户仍反馈缺少动效。使用computer-use核对其实际ChatGPT内置浏览器现有localhost:5173/#gallery：页面已加载原目录新版CSS，业务布局交替正确，但prefers-reduced-motion为reduce；所有作品立即可见、文字无延迟。因此单看文件同步及指定动态偏好的测试结果不能证明用户当前浏览器会播放。

用户明确缺少图片从两侧入场、文字延迟跟上。Agent选择在展览标题下增加播放/暂停按钮，默认继续遵循系统偏好；点击后以本页选择覆盖入场，并用localStorage的miao-gallery-motion记住play/pause。CSS改用本页is-entry-animated状态启用原有图文过渡；绣线进度使用同一状态。静态转播放先清除已展示记录，重新等待绣线到达；焦点内作品直接可读，存储受限仍可本次切换。没有更改系统/浏览器全局设置、作品间距、图片大小或原动效参数。

改动先在主线工作副本实现测试，确认后备份原工程两个文件到本次对话目录，再同步GalleryPage.jsx及gallery.css。动效开关修复前备份_2026-11-11.json记录备份及前后SHA256。原工程HEAD、全部暂存条目和其他跟踪文件仍与上轮清单一致；仅两份工作文件更新，未改其余原文件。

## 验证

2026-11-11展览播放修复，Windows/Node24.22.0/npm11.19.1/Edge，main/9fdee0b加本轮改动：npm test 48/48、npm run build 73模块通过；新增3项动效开关回归加9项展览/搜索/五页响应式与弹窗回归共12/12通过。原工程仅更新同样的两个展览文件，原HEAD、暂存区和其他跟踪文件校验保持原样。实际ChatGPT内置浏览器localhost:5173上读到系统减少动态为true；点击本页播放后，展览进入is-entry-animated，待入场图片横移约±55.87px、文字延迟0.12秒，滚动能触发作品，刷新后仍播放。截图当前浏览器展览动效已开启.jpg保存在本次对话目录。未更改系统或浏览器全局设置，未重建原目录dist/standalone/exe，未跑完整浏览器测试。

新增3项回归覆盖减少动态默认静态→主动播放左右侧移和延迟→刷新保留，正常动态→暂停/刷新保留及弹窗焦点恢复，存储不可用时仍可切换。首次有一项测试使用scrollIntoViewIfNeeded，只让作品完整可见但针结未进入触发线，已改为滚到针结中心后同一12项回归全部通过；未为该测试改变产品触发逻辑。

实际页面通过既有用户标签页操作：刷新出现播放按钮，点击后is-entry-animated生效；滚动观测下一作品进入is-visible并保留0.12秒文字延迟，再次刷新仍显示暂停按钮。系统减少动态保持true，未动任何系统偏好。当前浏览器展览动效已开启.jpg是该用户页面的验收截图。原工程5173开发服务仍可用。
